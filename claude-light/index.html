the problem

Most of what a coding session sends, the model has seen before

Rediscovered every session

A general agent starts each session knowing nothing about the repo, so it reads files through tool calls until it finds the code. Each round trip carries the context that came before it.

Whole files for one method

The answer usually lives in two or three methods. Reading the 1,500-line files they sit in pays for the other 1,400 lines on every turn of the conversation.

The big model for small questions

"Where is this called?" does not need the model you would ask to redesign the module, but a tool that always uses one model bills it at that rate anyway.

claude_light does the finding before the model is involved: the repo is indexed on your machine, each question gets only the methods that answer it, and the model is chosen by what the question needs.

how it works

Index once, retrieve per question, cache the rest

01

Index once

tree-sitter splits source files into one chunk per method, each keeping its imports and class header. A static embedding model indexes them in seconds; a transformer model catches up in the background. Saving a file re-indexes just that file.

02

Retrieve per question

Each question pulls only the chunks that clear two floors: a similarity of 0.35, and 60% of the best hit. The effort level sets the budget, from 1,500 tokens for a lookup to 9,000 for a design question.

03

Cache what does not move

The directory tree and your Markdown docs form a system prompt cached for an hour. Three cache breakpoints mean a follow-up about the same code pays full price only for the new question.

features

Built for asking, and for the edits that follow

ROUTING

Haiku for lookups, Opus for design

A router scores each question and picks Haiku, Sonnet or Opus with a matching retrieval budget. /why shows the model, the budget and every chunk that was sent, with its score.

EDITS

Changes you approve, commits you can undo

Proposed edits are lint-checked and shown as a diff before anything is written. Approved edits are committed with a Claude: prefix, and /undo reverts the last one without touching your own work.

AUTH

Your subscription or your API key

With a Claude Pro or Team subscription it uses the Claude CLI's login. With an API key it pays per token, and a heartbeat checks every 30 seconds to keep the cache warm through idle spells longer than 4 minutes.

SAFETY

No shell commands unless you allow them

The agent runs nothing by default. --allow-command opens specific prefixes, such as your test runner. Permission rules, hooks and MCP servers inside the repo are ignored, so a cloned repo cannot grant itself commands.

HISTORY

Conversations that stay small

Only the last 6 turns are resent. /compact replaces the conversation with a summary, and /cost shows tokens, cache hit rate and spend for the session.

MEASURED

Savings a build checks

CI fails a change that raises token cost or lowers retrieval quality against committed baselines. The retrieval and routing benchmarks run offline, with no API key and no spend.

install

Install, sign in, ask

install as a tool
pipx install git+https://github.com/PIsberg/claude_light.git
# or
uv tool install git+https://github.com/PIsberg/claude_light.git
sign in, one of the two
claude auth login                     # Claude Pro or Team subscription
export ANTHROPIC_API_KEY=sk-ant-...   # or pay per token
then, from your project root
claude-light                                 # interactive
claude-light "what does OrderService do?"    # one-shot, answer on stdout

The first install pulls in PyTorch through sentence-transformers, about 1.5 GB. The macOS, Linux and Windows installers, the configuration options and the optional LLMLingua compression are in the README.

faq

Questions

Does it replace Claude Code?

No. It is built for one job: questions about a repository and the edits that follow. With a subscription, each turn runs the Claude CLI's own agent with the retrieved code already in its context, so it starts from the right methods instead of searching for them.

What leaves my machine?

What goes to Anthropic: the directory tree and your Markdown files, the chunks retrieved for the question, the question itself and the recent turns. Indexing and embeddings run locally, and the index is stored in .claude_light_cache in your project.

Which languages?

Per-method chunking covers Java, Python, Go, Rust, JavaScript and TypeScript. Without the tree-sitter grammars installed, files are indexed whole.

Do I need a GPU?

No. On a CPU the static model indexes claude_light's own 1,400 chunks in about 2 seconds, so the first question already has context. The transformer model takes about 380 seconds on the same chunks and runs in the background; its vectors are cached.

Is it affiliated with Anthropic?

No. claude_light is an independent tool from Deversity that calls Anthropic's API and the Claude CLI. Your Claude usage is billed by Anthropic under your own account.
